# 第一期整体框架与 Codex 用量查询：需求规格

## 1. 背景与目标

ADV 工作台需要先形成可持续扩展的固件端与电脑端基础框架，并完成第一个真实业务闭环：电脑端复用当前 Codex 登录状态读取使用额度，经 BLE 发送到 Cardputer-Adv，在设备上展示额度窗口、用量、重置时间和更新时间。

本期重点不是完成草稿中的所有模块，而是验证以下主链路成立：

```text
Codex App Server
  → 电脑端 Codex 适配器
  → 统一状态与消息协议
  → BLE
  → ADV 会话与路由
  → Codex 页面
```

## 2. 功能需求

### R-01：ADV 正式工程与分层框架

- 建立可独立构建的 Cardputer-Adv 正式固件工程。
- 固件至少划分 Application、Core Services 和 Platform 三层，业务页面不得直接操作 BLE、键盘或显示驱动。
- 建立 Codex、快捷脚本、剪贴板、设置四个模块入口；本期只有 Codex 模块具有实际业务内容，其余模块显示占位内容。
- 开机默认进入 Codex 模块。

### R-02：基础导航与全局页面框架

- 顶部持续显示四个模块图标、第五模块预留位置和固定 BLE 连接图标。
- 支持 `Fn + 1` 至 `Fn + 4` 直接切换模块，支持 `Fn + ←` / `Fn + →` 循环切换模块。
- 断开连接时允许切换模块高亮，但内容区统一显示等待电脑连接，不执行模块业务操作，也不显示上一连接的数据。
- 页面更新不得阻塞键盘与连接状态处理。

### R-03：电脑端正式工程与分层框架

- 建立可启动、可测试的电脑端后台工具。
- 至少划分 Application、Core Services、Platform 和 OS Adapters；Codex 业务不得直接依赖 BLE 库或具体操作系统 API。
- 建立应用启动、模块管理、消息路由、连接会话、配置加载和本地诊断日志的最小实现。
- 单个业务模块初始化或运行失败时，程序继续运行并保留连接诊断能力。

### R-04：BLE 会话与统一消息协议

- ADV 作为 BLE 外设广播工作台服务，电脑端作为中心端发现、连接和断线重连。
- 同一时刻只维持一个活动业务连接。
- 连接后先完成 `system.hello`，协商协议版本、电脑标识、显示名称和支持能力；不兼容时不得继续业务同步。
- 业务消息统一使用 `event`、`actionId`、`execId` 以及 `payload` 或 `result`，并保留 `system.*`、`codex.*` 命名空间。
- 传输层负责必要的分片、组装、超时和 JSON 格式校验；业务层不感知 BLE 包边界。
- 本期不实现应用层自动重发。

### R-05：统一配置加载

- 电脑端从严格 JSON 配置读取 `configVersion`、公共 `settings` 和动作列表。
- Codex 默认刷新间隔来自 `settings.codex.refreshIntervalSeconds`，缺失时使用 300 秒安全默认值并记录诊断信息；握手完成后将该非敏感设置同步给 ADV，由 ADV 使用。
- 非法配置应产生明确错误；能够隔离的单项错误不得阻止其他合法配置或基础程序启动。
- 本期建立 Action Registry 的基础结构，但只注册和执行 Codex 用量动作。

### R-06：Codex 登录状态与用量查询

- ADV 通过 `codex.usage.read` 请求发起查询；电脑端收到请求后，才通过 Codex App Server 读取账户状态并调用 `account/rateLimits/read` 获取 ChatGPT Codex 额度。
- 电脑端不得自行周期查询，也不得在没有 ADV 请求时主动推送用量。
- 复用电脑现有 Codex 登录状态；不得要求用户另行把 Codex Token 写入本项目配置，也不得向 ADV 发送凭证。
- 支持官方返回的单额度桶与多额度桶结构，优先使用多桶视图；页面不得假定额度一定是固定的“5 小时 + 每周”两项。
- 每个可展示窗口至少保留已用百分比、窗口持续分钟数和下次重置 Unix 时间；缺失的可选字段不得导致进程或固件崩溃。
- 能区分未登录、查询中、查询失败、有新鲜数据和使用缓存数据。

### R-07：查询调度与缓存规则

- ADV 是查询调度的唯一发起方；电脑端只被动处理请求并返回对应结果。
- BLE 会话完成握手后，如果当前处于 Codex 页面且没有可用数据，由 ADV 立即发起一次查询。
- 用户在已连接的 Codex 页面按 `Enter` 时，由 ADV 立即发起一次手动查询。
- Codex 页面保持前台时，ADV 按同步到设备的配置间隔自动发起查询；默认间隔为 300 秒。
- 切换到其他模块后，ADV 停止 Codex 自动查询计时，不产生新的用量请求；电脑端因此不会继续后台查询或推送。
- 返回 Codex 页面时，如果没有数据或现有数据已超过刷新间隔，由 ADV 发起查询；数据仍新鲜时继续展示，并从最近一次查询完成时间计算下一次刷新。
- 前一次查询未结束时，ADV 不发送新的手动或自动请求；电脑端也必须拒绝或合并意外出现的并发请求，不并发访问 App Server。
- 查询失败后保留正常刷新节奏，不进行高频自动重试；用户仍可按 `Enter` 手动重试。
- 当前电脑连接期间可继续展示最近一次成功数据并标记为缓存/过期；断开后立即清除该会话数据。

### R-08：Codex 数据同步

- ADV 发送 `codex.usage.read` 请求并为每次查询生成新的 `execId`；电脑端只返回该请求的响应，并原样携带 `execId`。
- 消息结果包含稳定状态代码、可展示摘要、标准化额度窗口数组和数据获取时间。
- ADV Message Router 将该消息交给 Codex 模块，未知字段可忽略，缺少必需字段时进入明确错误状态而不是重启。
- 用量数据只属于当前连接会话，不持久化为跨电脑业务缓存。

### R-09：Codex 页面展示

- 页面按实际窗口数量动态展示，不为空窗口保留占位行。
- 每个窗口展示窗口时长、已使用百分比、进度表达和距重置剩余时间或明确的重置时间。
- 页面展示数据更新时间。
- 页面能够表达：等待连接、正在查询、正常、未登录、查询失败、缓存数据六类状态。
- 百分比和窗口字段异常时使用安全降级文案，不绘制越界进度。

### R-10：中文最小可行性验证

- 固件页面、固定状态和操作提示尽量使用中文；受屏幕空间、通用技术术语或缺失字形限制时才使用英文短标签。
- 在真实 Cardputer-Adv 上验证断开提示和 Codex 状态文案的 UTF-8 中文显示。
- 记录所用字库方案的 Flash/RAM 影响、绘制效果和缺字表现。
- 如果中文方案不满足资源或清晰度要求，应停止扩大中文范围并回到需求/设计阶段确认英文短标签或字形子集方案。

## 3. 非功能需求

### NFR-01：可维护性

- Codex App Server 接入必须封装在独立适配器中，解析结果转换为项目内部稳定模型。
- 具体 BLE 库必须封装在 Transport 实现中，路由与业务测试可脱离真实 BLE 运行。
- 仅在存在复用或隔离价值时新增公共抽象，不为未审核功能预先实现复杂扩展点。

### NFR-02：可靠性

- 无效消息、未知动作、Codex 查询错误和单模块异常不得触发设备重启或电脑端进程退出。
- BLE 重连采用退避策略，Codex 查询无紧密循环。
- 状态切换后不泄露上一台电脑的用量信息。

### NFR-03：性能与资源

- 键盘导航和本地页面切换应即时响应，不等待网络查询。
- 固件只在状态或页面内容变化时刷新必要画面。
- 电脑端空闲时不得持续占用明显 CPU。

### NFR-04：可验证性

- 消息编码/解码、路由、Codex 响应转换、刷新调度和页面状态模型应优先具有脱离真机的自动化测试。
- BLE 连接、导航、中文显示和最终页面效果使用明确步骤进行人工真机验证。
- lint、编译和类型检查仅作为基础兜底，不能代替新增逻辑测试。

## 4. 验收标准

1. 电脑端和 ADV 固件均可从干净环境按项目说明完成构建，电脑端可正常启动。
2. ADV 开机进入 Codex 页面，四模块顶部框架和规定的全局导航生效，三个非 Codex 模块明确显示占位状态。
3. 电脑端与 ADV 完成 BLE 连接、`system.hello` 和双向消息传输；断开后 ADV 清除用量并显示统一等待提示，之后可重连恢复。
4. 电脑已登录 Codex 时，ADV 展示 App Server 返回的实际额度窗口、已用百分比、重置时间和更新时间。
5. 未登录、查询失败和短暂失败后使用缓存均有不同且明确的页面状态。
6. 自动化测试覆盖多额度桶、单额度桶、可选字段缺失、异常百分比、查询互斥、`Enter` 手动查询、Codex 页前台 300 秒调度和离开页面后停止查询。
7. 真机验证 `Fn` 导航、连接图标、断开清理、Codex 页面和中文最小文案；人工验证结果由用户确认后才能认定最终通过。

## 5. 范围外

- 快捷脚本的配置同步、执行队列和结果展示。
- 剪贴板复制、模拟粘贴及操作系统权限处理。
- 设置模块的亮度、Wi-Fi、配对管理和版本详情业务。
- Codex 当前任务状态、会话管理、批准、拒绝、取消和输入指令。
- `account/usage/read` 的 Token Activity 统计展示。
- 额度重置操作、购买额度或通知工作区管理员。
- Wi-Fi 或 USB 业务通信。
- ADV 直接访问 Codex/OpenAI 服务。
- Windows、macOS、Linux 全平台同时完成正式验收；本期只完成一个首发平台闭环，其余平台保留适配边界。
- 自动更新、安装包签名、系统级开机自启和集中日志/审计平台。

## 6. 人工确认点

- Codex 页面最终图标、字号、进度条和状态文案由用户以真机效果确认。
- 中文字体是否继续采用中文、改为有限字形子集或使用英文短标签，以真机资源与清晰度验证结果为准。
- BLE 在首发电脑平台的权限授权、设备发现和真实 Codex 查询流程由用户完成人工确认。

## 7. 待确认问题

无。

首期按当前开发环境以 **macOS** 作为正式开发与验收平台；核心架构保持跨平台，Windows/Linux 适配不在本期实现范围内。
