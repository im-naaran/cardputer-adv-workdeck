# CPU 档位与开机自动 Light-sleep：技术设计

> 状态：已确认

日期：2026-09-11。追踪 [需求](requirements.md)。仅设计，不修改源码、构建或依赖。

## 1. 总体方案

CPU 配置、屏幕状态和芯片自动睡眠分别管理。初始化期间禁止睡眠；配置、外设、键盘唤醒、队列通知和业务任务就绪后，释放初始化限制。亮屏本身不阻止睡眠，运行中的任务及必要外设操作决定是否允许睡眠。

```mermaid
flowchart LR
  A[启动与初始化] --> B[启用自动睡眠策略]
  B --> C[处理队列和到期任务]
  C --> D[有变化且屏幕可见时绘制]
  D --> E[计算最近截止时间并等待事件]
  E --> F[系统空闲且驱动允许时 Light-sleep]
  F -->|按键 / 无线 / 定时唤醒| C
  E -->|有事件或仍有任务运行| C
```

该图为目标运行关系，不表示应用显式调用睡眠函数。自动睡眠依赖操作系统和驱动协作，不能从“主循环正在等待”推断芯片已经睡眠。

## 2. SDK 可行性门槛（R-03/R-07/R-08/R-09）

现有预编译 Arduino SDK 未开启 PM/Tickless Idle；IDF 4.4.7 的 ESP32-S3 文档说明 Bluetooth 仍持有 `ESP_PM_NO_LIGHT_SLEEP`。因此不能直接承诺当前依赖组合可实现 BLE 在线睡眠。[电源管理](https://docs.espressif.com/projects/esp-idf/en/v4.4.7/esp32s3/api-reference/system/power_management.html)

先做独立验证构建，固定 SDK、Arduino 组件、BLE 栈、工具链和配置，记录两类证据：PM 能力与锁状态；真机 BLE 连接/广播期间的睡眠驻留和通信结果。仅 API 返回成功不算满足条件，禁止绕过驱动禁睡锁。

候选路线为可配置 ESP-IDF 工程结合兼容 Arduino 组件，或重编当前 Arduino 底层库。先核实当前版本的控制器能力；若无法满足在线睡眠，提交具体候选版本、时钟要求、兼容影响和回退方案再决定迁移。当前不指定未经验证的升级版本，不将升级本身作为成功保证。

门槛未通过时：CPU 配置设计仍有效；Light-sleep 保持“能力未验证/不支持”，禁止进入正式集成和默认发布。可继续只读调查及独立验证设计，不能将功能标记完成。

## 3. CPU 配置与统一平台入口（R-01/R-02/R-09）

新增 `application/settings/power_config.*`，复用 ConfigFileStore，保存 `/config/power.json`：

```json
{"cpuFrequencyMhz":160}
```

只接受整数 80/160/240，拒绝未知键、尾随垃圾和内嵌 NUL 绕过。缺失或非法文件保留默认 160，不启动写盘。读失败与格式损坏分别报告，不覆盖无法读取的文件。

新增窄平台接口 `PowerAdapter`：`configure(frequency, allowAutomaticSleep)` 返回状态与实际频率；`frequencyMhz()` 读取实际值。具体命名可按项目风格微调。平台入口是唯一频率所有者：

- 现有非 PM 构建使用 Arduino 固定改频接口；未来 PM 构建使用 SDK PM 配置，最小/最大频率均设为选定档位，不额外引入 DFS。
- 不在 PM 运行时并行调用裸改频接口。改档时保留既定自动睡眠策略；失败则保留/恢复上一有效配置并读取实际状态，恢复也失败则报告故障、禁用自动睡眠，不伪报目标值。
- 构建启动频率拟设为 160 MHz，应用在无线启动前加载持久化值；不是承诺 ROM/bootloader 全程 160 MHz。

保存流程：校验 → 应用并核实 → 比较磁盘 → 必要时原子替换 → 回读校验。应用失败不写入；写入/回读失败保留当前实际频率并提示，可再次保存；回读失败不得承诺文件未变化。

SettingsController 引用配置服务；SettingsPage 首页追加“CPU频率”，复用四行滚动布局、方向键/Tab 调档和行内反馈。正常显示实际 MHz；失败提示持续显示，Enter 重试。应用失败时保留待重试档位与实际档位的区别，避免 Enter 意外保存旧档位；改变选择替换待重试目标。返回不自动丢弃错误信息。

## 4. 空闲等待与截止时间（R-03/R-04/R-07/R-08）

复用 ScheduledTaskService 的原有注册和 tick 语义，新增 `nextWaitMs(now)`，返回可选剩余时长：无启用任务为空、已到期为 0。统一使用回绕安全差值，查询不得改变任务状态。醒后过期周期仍按原逻辑执行一次，不按睡眠时长补发多次。

新增应用层 `IdleCoordinator`，只汇总下一次必须处理的时间和待处理事件，不复制业务状态机。适配层负责带通知的 RTOS 等待及 PM 状态；业务控制器继续由主循环调用。

| 来源 | 需要唤醒的条件 | 第一阶段处理 |
| --- | --- | --- |
| 调度器 | Codex、电量、授时、可见时间检查 | 复用 nextWaitMs |
| BLE | 接收/连接/断开/发送状态变化，发送与请求超时 | 回调入队后通知；补发送及请求剩余时间查询 |
| Codex、授时、Actions | 请求超时、提示消失等 | 各模块暴露自有下一处理时间，协调器取最小值 |
| SettingsPage | 600 ms 防抖、提示期限 | 暴露下一处理时间，保留原自动保存语义 |
| ScreenPowerController | 息屏到期 | 暴露剩余时间，按住键时沿用原规则 |
| Wi-Fi | 扫描、连接、关闭重试 | 活动及关闭失败期间保守禁睡，保留 10 ms 服务等待；稳定关闭后释放 |
| USB/串口 | 输入命令、输出完成 | 未验证前调试连接期间保守禁睡并保留有界轮询 |

循环保留原处理顺序：队列/输入 → 控制器与定时任务 → 发送 → 屏幕状态与绘制 → 重新取时间、计算最短等待 → 等待。执行耗时操作后不能用旧 now 计算等待。所有原有期限均需登记，遗漏来源不能靠无限等待掩盖。

事件通知必须可累计或保持待处理状态。入队先于通知；检查空队列与开始等待之间出现的事件不得丢失。BLE ISR/回调只通知和入队，业务仍在主循环。初始化时即建立通知目标，准备完成前不得睡眠。

## 5. 键盘与显示（R-05/R-06）

TCA8418 保持供电，共享 I²C 保留。GPIO11 采用经硬件确认的有效电平唤醒，候选低电平 GPIO wakeup；普通 CHANGE ISR 不足以替代睡眠唤醒。[GPIO 唤醒说明](https://docs.espressif.com/projects/esp-idf/en/v4.4.7/esp32s3/api-reference/system/sleep_modes.html)

当前库自行注册 ISR，不能用第二次 attachInterrupt 覆盖它。验证阶段确定可维护的库扩展点或纳入版本控制的最小补丁：保留原 ISR 行为并通知应用；醒后在任务上下文显式核对中断电平和 FIFO，弥补睡前已低电平及未形成新边沿的情况。每轮有界排空事件，仍有积压时继续通知并禁止等待；不在 ISR 中读 I²C。

复用 KeyboardAdapter/ScreenPowerController：亮屏首键照常输入，息屏首键只唤醒且等全部释放后恢复业务。快速按下/释放不能合并成最终空快照而丢键，需按事件顺序保留物理活动。

继续按 redrawRequested 和可见内容变化绘制，不增加睡眠帧率定时器。CPU 睡眠时零推帧，LCD 保留末帧；背光时钟选择、睡眠保持与中文帧传输通过实验确认。活动 SPI/DMA 传输完成前持有适当保护，不能只保护绘制函数调用的同步部分。

亮屏有可见变化时刷新；息屏后台只更新缓存，用户唤醒先绘制最新帧再恢复亮度。芯片定时唤醒不改变屏幕状态，也不重置按键活动时间。

## 6. 睡眠状态、锁与故障（R-03/R-07/R-08/R-09）

状态至少区分能力不可用、初始化中、策略启用、故障回退；“策略启用”不等同“正在睡眠”。驱动自行拥有的 PM 锁不由应用释放。应用锁仅覆盖初始化、未验证外设操作及必要传输，并在成功、失败、取消路径配对释放。

Codex 等待主机响应时，是否可以继续自动睡眠取决于已验证的无线驱动：满足门槛后允许在收发间隙睡眠，由无线事件或请求超时唤醒；不可仅发完请求便关闭 BLE。广播、断开和重新 hello 仍走原会话流程。

实验诊断包含配置/实际频率、PM 状态/错误、锁归属和可获得的睡眠驻留指标。无真实驻留指标时必须用可靠硬件测量补证，不以主循环等待时长冒充睡眠时长；不记录凭据或业务内容。

保留禁睡构建与 240 MHz 档位作为独立回退变量。PM 初始化失败保留业务可用并记录明确错误，不能展示“睡眠已启用”。USB 调试禁睡仅为实验限制；正式默认启用前应确认 USB 下的产品行为，不能隐藏该限制。

## 8. 复用与实现约束

新能力仅限独立电源配置、窄平台电源/等待适配和空闲协调。其余扩展既有调度器、队列、键盘及控制器，不新增第二套调度、输入路由或业务线程。

关键注释解释改频所有权、等待竞态、GPIO/FIFO 唤醒、锁释放和屏幕首键语义；不为简单转发增加抽象。SDK/键盘库变更必须版本化可复现，不编辑安装缓存。生产实现须追踪需求和后续任务编号。
