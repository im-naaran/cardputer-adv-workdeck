# CPU 档位与开机自动 Light-sleep：需求

> 状态：已确认

日期：2026-09-11。确认依据：用户在讨论后明确“好的，按此方案，通过skill<spec-driven...>进行设计”。本文件整理该确认的需求基线，技术设计和任务拆解仍需分别确认。

## 目标

开机初始化完成后持续允许自动 Light-sleep，有任务或事件时唤醒处理，空闲后继续睡眠；CPU 工作频率可配置。保持现有后台业务和屏幕交互，功耗收益由实机对照确定。

## 功能需求与验收

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| R-01 | CPU 默认 160 MHz，可选 80/160/240 MHz | 新设备默认正确；逐档设置与重启后实际频率符合配置；不开放其他档位 |
| R-02 | CPU 设置自动保存、失败可见且可恢复 | 设置入口可离线使用；缺失/损坏配置使用默认且不静默写文件；应用失败不保存目标值；保存失败显示当前实际频率并可重试；重复值不重复写 |
| R-03 | 初始化完成后自动睡眠，独立于屏幕状态 | 亮屏静止与息屏均能测到真实睡眠驻留；唤醒处理后恢复自动睡眠；运行任务时不会强制睡眠 |
| R-04 | 后台定时功能保留 | Codex 用量、电量、授时及超时按原计划推进；正确处理周期调整、停用、时间回绕；睡眠跨周期不产生补发风暴 |
| R-05 | 键盘唤醒与原交互一致 | 亮屏首键正常执行；息屏首键只唤醒，释放后的下一键正常；短按、长按、修饰键及睡前按键不丢失、不重复触发动作 |
| R-06 | 屏幕按变化更新 | 睡眠期间不推帧；亮屏保留画面，按键/可见数据/必要时间变化后更新；息屏后台更新不点亮，用户唤醒绘制最新状态 |
| R-07 | 保持 BLE 会话与异步任务完整 | 广播可发现，连接可保持，Codex 请求从发送到响应/超时完整处理；脚本、粘贴及重连可用；不以周期性断连重连替代在线睡眠 |
| R-08 | 外设操作与存储安全 | Wi-Fi 扫描/测试/关闭重试及时推进；显示、I²C、Flash、背光和 USB 行为经验证；活动完成后释放应用禁睡条件 |
| R-09 | 能力检测与回退可观察 | 无 SDK 支持、初始化失败或硬件验证未过时，不宣称启用成功；保留禁用睡眠及恢复 240 MHz 的回退路径 |

## 非功能要求

- 主循环继续串行业务处理；ISR 不绘图、读 I²C、写文件或处理协议。
- 睡眠计划覆盖最近截止时间和异步事件，不能依赖睡眠中的代码自行退出睡眠。
- 功耗测量区分供电和测量点，固定亮度/电量/主机/信号条件，比较平均电流、操作耗时和能耗。
- 设置/唤醒交互与 BLE 真机结果独立记录，自动化和构建不替代实机验收。
- 不降低已有业务刷新周期；只减少无变化绘制与无事轮询。验收中分别记录唤醒开销、业务耗时及原超时边界，异常视为未满足需求。

## 范围外

离线手动休眠、Deep-sleep、40 MHz 及以下档位、额外动态调频策略、BLE 参数调优、协议改版和桌面功能修改。SDK 迁移在设计中评估，未授权实际升级依赖。

## 待确认问题

需求无新增阻塞问题。SDK/BLE 能否满足 R-03/R-07 是技术验证门槛，详见设计；门槛未通过时功能保持未完成，不静默更改需求。
