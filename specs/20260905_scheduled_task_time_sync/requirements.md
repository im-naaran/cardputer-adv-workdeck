# 定时任务与系统授时：需求规格

## 背景与目标

依据已确认的定时任务与授时方向，在现有 ADV 工作台中建立轻量统一周期任务服务，实现跨页面 Codex 刷新和电脑授时。ADV 拥有调度，桌面只响应请求；周期计算不依赖日历时间。

## 功能需求

### R-01：统一任务生命周期

- 提供注册、查询状态/周期、立即执行、启停、修改周期、重设周期起点和取消能力；静态任务 ID、固定 8 个槽，不允许电脑配置注入固件回调。
- 拒绝重复 ID、非法周期和容量溢出，失败不改变已注册任务。合法周期范围、未知 ID 返回行为在设计中明确定义。
- 暂停保留任务；恢复从当前单调时间开始等待完整周期，不自动立即执行。已启用任务重复启用不应意外推迟执行。
- 立即执行允许对暂停任务执行一次，但不恢复自动任务；启用时同时重设周期起点。单独重设起点不执行回调、不改变启停状态。
- 更新周期从当前时间重新计算，不改变启停状态；取消释放任务槽。
- 注册时应有明确单调时间基准；支持选择首次立即执行，两个首批网络任务默认不立即执行，等待 hello。

### R-02：调度与短时计时边界

- 当主循环 tick 发现到期时，每个任务最多执行一次，不补跑错过的多个周期；先更新时间基准再调用回调，支持回调暂停或取消自身。
- 同时到期按注册顺序执行，系统授时优先于 Codex；不存在回调递归触发自身造成无限执行的情况。
- 所有长期跨页面周期都交由统一服务；现有每分钟电量/相对时间重绘只由任务设置绘制标记，绘制仍在主循环完成。
- 协议分片间隔、请求超时/短时重试、按键和动画计时可局部维护。
- 所有周期、超时与重试使用单调时间，兼容正常持续运行时的 `millis()` 回绕；日历时间前跳或后跳不得改变任务触发。

### R-03：Codex 后台刷新

- 默认启用、周期 300 秒；hello 下发周期沿用现有 1～86400 秒限制，应用到统一任务。切页不停止刷新。
- 会话就绪、支持 `codex.usage.read`、自动任务启用时，首次连接和重连立即尝试一次刷新；重复 hello 不应重复启动任务或造成重复请求。
- 未就绪、不支持 capability、已有请求在途时跳过发送，不能每帧重试；一次周期回调被跳过不补跑。
- 自动周期按触发起点计算；手动请求成功提交发送后重设周期起点，提交失败不推迟下一周期。
- 页面激活只影响输入/绘制，不影响请求、响应和缓存更新。

### R-04：Codex 页面启停

- Codex 页面 `Enter` 手动刷新，`Fn+Enter` 切换自动刷新；恢复后等待完整周期，用户可另按 Enter 立即刷新。
- 关闭自动刷新保留当前缓存，不取消已经发出的请求；有效响应仍更新缓存。关闭状态重连后不主动查询。
- 页脚展示实际配置周期（默认“自动 5m”）或“自动已关”，空数据、加载和错误状态也应能识别当前设置；修改后立即重绘。
- 启停在切页和断线重连后保留，本次开机有效；重启恢复默认启用。断线仍沿用现有用量缓存清空策略，不保留其他电脑的用量。

### R-05：桌面授时协议

- 桌面默认注册 `system.time.read` 并在 hello capabilities 声明，不依赖 Codex 动作是否启用或查询成功。
- ADV 使用现有 request/actionId/execId/payload 信封，请求 payload 为 `{}`。
- 成功响应为现有 result 信封，data 包含整数 `epochMilliseconds` 与整数 `utcOffsetMinutes`，表示同一采样时刻的 UTC Unix 毫秒和电脑当地 UTC 偏移。
- 桌面收到请求时读取时间，不创建周期授时器；响应与请求保持相同 actionId 和 execId。
- 沿用版本 1 和能力协商；旧桌面未声明授时能力时不发送授时请求，Codex 可继续工作。

### R-06：系统时间状态

- 仅接受合法整数、平台可表示的 Unix 时间与合法时区偏移；字段缺失、类型错误、溢出和系统设置失败不能标记授时成功或破坏上次有效状态。
- 系统时间存储 UTC，偏移仅用于当地时间转换，禁止给 Unix 时间重复加偏移。
- 提供当前时间、本次开机是否成功授时、最近成功授时的单调时间及偏移查询。成功授时不等于已证明电脑时间准确。
- 本次开机首次成功前标记未授时；完全断电重启后重新等待授时。断线后继续走时，并保留最近成功状态与同步年龄。
- 偏移作为最近一次同步快照，后续同步更新；首版不自行推算夏令时。

### R-07：授时周期与恢复

- 默认启用、3600 秒；首次有效 hello 且声明 capability 后立即同步，不等待打开某个页面。
- 成功授时后以成功时刻重设下一小时周期。
- 同一电脑重连：未成功授时、上次同步失败待恢复或距最近成功已满一小时时立即补同步；未到期则保持原有成功时刻对应的截止时间，不能因重连延后一小时。
- 不同电脑 hello 后立即重新同步电脑时间及偏移。重复同一会话 hello 不应产生重复请求。
- 断线时不发送；跳过的周期回调不能更新最近成功授时记录，也不能丢失应补同步状态。
- 请求失败或超时允许控制器有限次数的短时重试；耗尽后等后续周期或重连恢复，禁止每帧重试。具体超时、间隔、次数在设计中给出。

### R-08：共享请求关联与故障恢复

- Codex 与授时使用共享 ExecIdGenerator，同一会话不重复，重连后不能复用仍可能对应迟到响应的 ID。
- 每个动作最多一个在途请求，不同动作可并行等待；授时不得被 Codex 查询耗时阻塞。
- 只接受 `event=response` 且 actionId、当前非空 execId 均匹配的响应；超时、断线后的旧响应不得覆盖新状态。
- 两种请求都必须有设备侧有限超时：丢失响应后释放在途状态；Codex 保留已有数据并标记失败，后续手动或周期请求可恢复，不引入 Codex 高频自动重试。
- 断线清空在途 ID、待发送消息与局部重试；任务注册、启停和本机系统走时状态保留。

### R-09：发送与主循环响应性

- 调度回调只提交有界发送工作或事件并快速返回，不进行带分片延时的整条 BLE 发送。
- 两端均按完整 JSONL 消息串行分片，不允许两个动作分片交错；发送队列容量固定，满队列返回失败并允许后续恢复。
- 请求等待时间须覆盖发送排队与响应阶段，避免排队或丢包使在途状态永久卡住。设计需明确取消尚未发出的过期消息的处理。

## 非功能需求

- 不为每个任务创建线程，不在定时触发时写 NVS，不升级依赖或改变部署配置。
- 复用已有时钟、消息路由、注册表、会话、键盘与缓存能力；系统时间平台操作可替换以支持 native 测试。
- 时间、时区、重试与会话失效等关键边界需注释，保持小范围修改。
- ±36 ms/小时仅是原方案引用的计时器量级换算；0.1～0.5 秒 BLE 授时偏差是待测估计，不作为已验证成果。

## 验收标准

| 编号 | 追踪 | 场景与预期 | 验证方式 |
| --- | --- | --- | --- |
| AC-01 | R-01、R-02 | 重复注册、槽满、非法周期、暂停/恢复、立即执行、改周期、取消、自取消行为符合约定；迟到 tick 不补跑 | native 假时钟测试 |
| AC-02 | R-02、R-06 | 单调计时跨回绕、日历前后跳时任务仍按原周期；每分钟绘制标记来自统一调度 | native 测试及源码检查 |
| AC-03 | R-03 | hello 按能力触发首次刷新，切走超过周期仍请求，返回看到新缓存；不支持能力时不发送 | 控制器测试及真机 |
| AC-04 | R-04 | Fn+Enter 关闭后跨两个周期无自动请求，Enter 可刷新；恢复后完整周期才触发，页脚即时更新 | 输入/状态测试及真机布局 |
| AC-05 | R-03、R-04 | 手动提交成功重设起点，失败不重设；关闭期间重连不查询，重启恢复默认 | native 测试及真机 |
| AC-06 | R-05、R-06 | 双端解析共享授时 fixture；整数/时区/缺字段/溢出/设置失败/未知字段均有断言 | pytest、native、共享 fixtures |
| AC-07 | R-07 | 首次、成功后一小时、到期断线后重连各触发一次；一小时内重连不推迟原截止时间；切换电脑重新同步 | 假时钟及会话测试 |
| AC-08 | R-07、R-08 | 丢响应后超时释放，授时有限重试，Codex 后续刷新可恢复；旧响应不覆盖 | 故障注入测试 |
| AC-09 | R-08、R-09 | 同时到期 ID 不重复，授时先提交，Codex 慢响应不阻塞授时，整条分片不交错；队列满和断线可恢复 | 双端集成测试及真实 BLE |
| AC-10 | R-06、R-07 | 非睡眠正常运行下记录首次同步误差及下一次同步前误差，二者差值的绝对值不超过 1 秒；记录链路延迟与测量方法 | 真机一小时测量，不以构建替代 |
| AC-11 | R-06 | 完全断电后未授时，重新连接后获得时间；断线期间持续走时 | 真机及状态测试 |

自动化验证和人工确认分开记录。Phase 1 只检查文档，不执行构建或声称真机验收完成。

## 范围外

- 日历闹钟、指定时刻任务、cron、任务管理设置页、桌面下发任意回调。
- 启停状态持久化、Wi-Fi/NTP、RTC 硬件持时承诺、Light/Deep Sleep。
- TOTP、独立时钟页面、改造 Codex 重置倒计时的数据来源。
- 往返延迟补偿、时区数据库、后台主动推送、依赖升级。

## 非阻塞假设

- 采用原方案建议的 Fn+Enter，当前输入结构已有支持，实机组合键和文案布局在实现验收中确认。
- 短时重试次数和平台可表示时间范围属于设计参数，Phase 2 明确后再进入任务拆解。
- 本次按正常持续运行设计；不支持主循环停止超过完整 32 位 millis 周期后推算实际经过的多个回绕周期。

## 待确认问题

无。以上边界随本需求草稿整体确认后进入设计。
