# ADV 模块运行时配置：需求

## 目标

Codex 刷新周期由 ADV 的模块 JSON 文件维护，默认 300 秒；desktop 只被动处理业务请求。为后续 settings 模块提供保存并立即应用的能力，本次不实现设置页面。

## 功能需求

### R-01：模块独立运行时文件

- Codex 拥有独立 JSON 配置文件，刷新周期字段使用秒；不是编译期头文件，修改后无需重编固件。
- 首版配置字段为 `refreshIntervalSeconds`，默认 300 秒。建议合法范围 60～3600 秒，保持现有用户配置范围；不把调度器底层的最大范围直接作为产品配置范围。
- 文件在设备重启后保留。源码目录下的模块默认样例与设备上的实际文件明确区分；存储介质、路径、初始化及部署方式在设计阶段落实。
- 默认值集中定义，不在页面、消息和会话中重复提供刷新配置。

配置内容示意：

```json
{
  "refreshIntervalSeconds": 300
}
```

### R-02：按需读取最新值

- 模块配置的读取入口每次调用都读取当前文件并校验，不永久缓存首次读取结果。
- 启动加载；模块需要重新应用配置时读取文件。后续 settings 读取配置用于展示时也通过同一入口获取当前值。
- 调度器使用最近一次合法配置对应的运行周期；不要求每帧绘制、每次 tick 都读取文件。
- 本次受支持的修改方式必须有保存后立即重新读取并应用的路径。不能仅在下一个旧周期到期或重启后生效。
- 绕过保存入口直接改文件时，通过显式重新加载入口或重启应用；本次不引入文件监视及高频轮询。此读取/变更语义已确认。

### R-03：保存后立即应用

- 提供可供后续 settings 使用的配置保存及应用入口；合法内容安全写入后重新读取并更新所属模块，调用结果明确成功或失败。
- 保存成功后，在主循环下一次调度判断前应用新周期并刷新页面状态，无需重连或切页。
- 周期实际改变时从应用时刻重新等待完整新周期。例如从 300 改为 60 秒，从修改生效时开始计 60 秒；不会继续等旧 300 秒，也不隐式立刻发送。
- 相同周期重复读取或保存不重设调度起点，避免刷新不断延后。
- 修改周期不改变自动启停、不取消在途请求、不清空缓存。处于关闭状态时仍保存新周期，恢复自动后等待该周期。

### R-04：异常及持久化边界

- 拒绝非整数、布尔、小数、缺少必需字段、非法范围和损坏 JSON；文件大小及未知字段策略在设计中明确。
- 首次无可用文件时采用默认 300 秒，提供可诊断结果；运行中读取失败保留最后有效任务周期，不能让模块停止或频繁重置。
- 非法保存不改变有效文件或运行周期；写入失败应明确失败并尽量保留旧有效文件。若写后重读失败，不声明已成功应用，保留旧运行状态并允许重试。
- 普通读取和周期触发不得写 Flash；不反复写入相同配置。挂载失败不能自动格式化并删除其他模块文件。

### R-05：桌面与协议去除周期控制

- 删除 desktop 刷新周期配置、默认常量及其内部字段，hello 不再下发 `codexRefreshIntervalSeconds`。
- 新固件忽略旧桌面 hello 的刷新周期字段，不允许电脑覆盖本地文件；保留协议版本、身份与能力协商。
- 原固件在新桌面 hello 缺少周期字段时使用自身默认值；通过现有兼容逻辑和 fixtures 验证这一边界。
- 旧 desktop 配置中的刷新字段迁移方式在设计中明确，README 同步说明，不能静默继续控制 ADV。
- 保留桌面 `requestTimeoutSeconds` 及 15 秒默认值，用于被动查询的 RPC 超时；去除重复默认定义，不删除超时机制。此次不改变设备 210 秒等待或授时参数。

### R-06：文档和扩展边界

- 根 README 说明配置文件如何部署、如何修改并应用；firmware README 说明模块文件、读取/保存/应用流程及扩展入口。
- desktop/protocol README 删除电脑控制周期的说明，保留各自代码与协议职责。
- 文件读取与硬件存储隔离，后续 settings 能复用入口；不建设通用配置中心、订阅总线或任意模块动态注册框架。

## 验收标准

| 场景 | 预期与验证方式 |
| --- | --- |
| 首次启动、文件存在、读取失败 | 默认或文件值符合约定；native 假存储覆盖 |
| 连续读取期间文件变化 | 下一次显式读取返回当前文件值，非开机缓存 |
| 300 改 60、60 改 300 | 保存成功后按应用时刻重设周期，页面显示一致；假时钟与设备验证 |
| 重复读取相同值 | 周期起点不变，到期仍能触发 |
| 关闭自动或已有请求时改值 | 不开启任务、不取消请求；恢复按新周期运行 |
| 非法内容、写失败、重读失败 | 文件/运行状态按 R-04 保留，错误可观察 |
| 重启 | 持久文件重新加载；实际文件系统和刷写行为由设备验收 |
| 新旧 hello 与旧桌面配置 | 本地周期不会被覆盖；迁移和兼容用例明确 |
| 桌面查询超时 | 删除刷新配置不影响 RPC 超时和错误响应 |

自动化验证解析、状态及保存流程；真机验证实际文件写入、重启持久化、页面反馈。构建不代替设备验收。

## 范围外

settings 页面、自动开关持久化、其他模块配置迁移、桌面远程配置、热插拔 SD、文件监视、授时周期调整及依赖升级。

## 待确认问题

无。用户回复“继续”，确认上述需求，包括按需读取与保存后立即应用、60～3600 秒范围、只持久化刷新周期以及桌面保留 RPC 超时配置。
