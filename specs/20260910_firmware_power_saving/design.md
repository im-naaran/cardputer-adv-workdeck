## 1. 方案与职责

采用应用层显示状态控制、共享调度下的电量缓存、现有 Wi-Fi 服务内的有界重试。硬件操作留在平台适配层，页面只消费状态和提交设置。

| 模块 | 决策 | 对应需求 |
| --- | --- | --- |
| `application/power/screen_power_controller.*`（新增） | 管理空闲时间、亮灭和唤醒输入抑制；纯状态逻辑，不读硬件、不写配置 | R-01～03 |
| `platform/keyboard_adapter.*` | 在既有扫描中提供物理活动与按住状态，不改变业务键映射 | R-01、02 |
| `application/settings/display_config.*`、`settings_controller.*`、`settings_page.*` | 扩展原配置、运行时显示值与自动息屏设置页 | R-01 |
| `application/power/battery_service.*`（新增）、`platform/battery_adapter.*`（新增） | 电池硬件读取独立于显示；缓存由共享调度更新 | R-04 |
| `main.cpp`、`application/app_shell.*`、`platform/display_adapter.*` | 接线、背光切换、绘制入口过滤；外壳直接使用电池快照 | R-02～04 |
| `application/codex/codex_page.*` | 复用时间格式化与视图，比较可见时间文字，减少周期性空刷新 | R-03 |

不新增通用电源管理框架、独立线程或第二套调度器。上述名称为实现约定，可在不改变职责的前提下贴合现有命名。

## 2. 显示状态与输入边界

### 状态

控制器使用三个状态，输出是否允许业务输入、是否允许绘制和本轮亮灭转换：

| 当前状态 | 事件 | 下一状态与动作 |
| --- | --- | --- |
| `Awake` | 无按住键，空闲达到非零超时 | `Off`；背光关闭 |
| `Awake` | 物理活动或按住键 | 保持亮屏，刷新活动时间 |
| `Off` | 物理按键按下或检测到按住键 | `WakeUntilRelease`；请求最新帧，消费本轮全部业务键 |
| `WakeUntilRelease` | 仍有键按住 | 保持亮屏，持续消费业务键，不触发息屏 |
| `WakeUntilRelease` | 全部释放 | `Awake`；本轮仍不分发业务键，从释放时重新计算空闲时间 |

下一轮新的按下事件恢复业务操作。唤醒门控位于 `InputRouter` 和 `handleKey()` 之前，因此全局 Fn/Alt 快捷键也不能穿透。

### 接口与时间

- 控制器持有 `state`、`lastActivityMs`、`autoScreenOffSeconds`；初始化为亮屏，活动时间为启动单调时间。
- `onKeyboard(activity, now)` 消费当前物理报告，并返回本轮是否允许分发业务事件；`tick(now)` 检查息屏边界；`setTimeout(seconds)` 更新策略，不伪造物理活动。
- `KeyboardActivity` 至少包含 `anyDown`、`changed`、`pressedThisUpdate`。按键集合比较包括普通键及全部修饰键；不依赖仅比较键数的 `isChange()`，也不只依赖 `takePressedEvents()`。
- 复用当前键盘扫描与快照；如底层一次更新聚合多条事件，核实能否捕获按下再释放，避免只看最终空集合而漏唤醒。无需额外全键盘扫描。
- 被抑制的事件仍必须取出并丢弃；`KeyPressTracker` 继续更新，不能将唤醒事件留到下一帧，也不能在仍按住时重置跟踪器造成新的按下事件。
- 使用现有 `elapsedMs()` 和 `uint32_t` 单调时间；所有配置时长远小于半个计时范围。按下与超时同一轮时先处理输入，按键优先。

### 背光与绘制

- 运行时用户亮度与亮灭状态分开保存。对硬件的有效亮度为：息屏时 0，否则 `brightnessLevel * 51`。
- 显示配置应用回调必须经过统一背光应用入口，避免以后在息屏状态应用设置时意外点亮。
- 息屏转换只调用背光接口一次；唤醒本轮先生成并推送最新帧，再恢复原亮度，避免短暂露出旧帧；初始化亮屏仍沿用原启动流程。
- `draw()` 先判断是否允许绘制，再检查并清除 `redrawRequested`。息屏期间不能提前清除该标记。
- 合并刷新只发生在主循环尾部；不释放/重建帧缓冲，不排队历史帧，不因唤醒调用查询、页面进入或动作执行入口。
- 业务已正常产生的新状态仍可在后续循环请求刷新，“唤醒一次”不禁止真实后续变化。

## 3. 显示配置与设置页

继续使用 `/config/display.json`，扩展为：

```json
{"brightnessLevel":3,"autoScreenOffSeconds":600}
```

- `autoScreenOffSeconds` 类型为 `uint32_t`，只接受 `0 / 60 / 300 / 600 / 1800`；0 表示永不。
- 原文件 `{"brightnessLevel":3}` 有效，缺省时长为 600；亮度仍必填。拒绝其他未知字段、错误类型、布尔值、非整数、越界值和尾随垃圾。
- 解析器当前限定 `doc.size() == 1`，需同步扩展；比较、编码、读回验证必须覆盖两个字段。
- `SettingsController` 持有完整当前生效的 `DisplayConfig`，使用完整快照保存；修正当前 `encodeDisplayConfig({level_})` 的亮度单字段构造，避免重置时长。
- 沿用亮度“先应用、再保存、失败就地提示”的语义。相同值已保存时不写 Flash；此前保存失败时允许用户按 Enter 重试保存当前值，不要求先切换到另一个值。
- 保存成功的状态与当前生效值分开处理；失败后另一项的保存应携带当前两项值。启动失败沿用默认配置和现有存储错误提示，不格式化文件系统。

设置首页在现有三项后追加“自动息屏 10分钟”，保留原三项索引；四行可在现有小屏空间内显示，调整首页可见行数为 4。进入 `kAutoScreenOff` 子页后用单行选项和就地反馈：

```text
自动息屏
< 10分钟 >
已保存
```

方向键按既有亮度交互调整档位、边界停留，Tab 循环；修改立即应用并保存，Backspace 返回。沿用离线可用、全局导航和反馈时效；不为五档枚举另设防抖系统。

## 4. 电量缓存与必要刷新

### 电池读取

- `BatterySnapshot` 包含 `level`（-1 表示未知）和 `charging`；迁移原 `DisplayAdapter::batteryLevel/batteryCharging` 的硬件读取到 `PlatformBatteryAdapter::read()`，不并存两条读取路径。
- `BatteryService` 注入读取回调，提供缓存及 `sample()`；只在快照变化时返回变化信号。无效百分比规范化为 -1，不使用失败读数推断关机或充电策略。
- 保留现有充电显示语义但每次采样一并缓存；该接口在 ADV 上的可用性仍有限，不新增充电判断逻辑。
- 在原 `ScheduledTaskService` 增加 `kBatterySample` 及合法 ID 判断，注册 60000 ms、启用、立即执行。注册回调承担启动首次采样，不在其他地方再采一次。
- 使用现有调度“到期执行一次并从执行时间起计”的行为，延迟不补跑，失败不提前重试；保持任务独立于 BLE 会话生命周期。
- 电池变化设置重绘标记；息屏只更新缓存。`AppShell::beginFrame()` 接收缓存快照，移除外壳内的充电状态硬件读取。

### 周期刷新

保留 `kDisplayRefresh` 的 60 秒检查节奏，但回调不再无条件置重绘标记：

1. 息屏立即跳过显示文字检查，唤醒会强制生成最新帧。
2. 亮屏且当前为已就绪的 Codex 页面时，复用 `makeView()` 和既有格式化函数，比较上次实际绘制的页脚及可见两行的重置文字。
3. 文字不同才请求重绘；其它静态页面没有周期性时间内容，不因这一任务重绘。
4. 每次实际绘制后更新比较基准，切页或连接状态切换时失效；比较范围不含屏幕外列表行。

仅增加小型可见时间快照，放在 Codex 页内部；不新增全局视图哈希、帧比较或通用差分渲染。当前事件触发刷新继续保留，不扩展为全项目无效按键重绘审计。原有反馈到期和业务状态更新仍由原控制器请求刷新。

## 5. Wi-Fi 自动收尾

### 参数与内部状态

- 首次释放立即执行；失败后最多自动重试 **3 次**，每次距上一次释放尝试完成至少 **1000 ms**。
- 自动重试总计最多带来 3 次额外调用；长时间未 tick 也只尝试一次，不补跑。
- 内部保存 `releaseRetryRequestId`、`releaseRetriesRemaining`、`lastReleaseAttemptMs`；无需注册共享周期任务，复用每轮运行的 `WifiService::tick()`。
- `WifiStatus` 增加只读 `releaseRetryPending`，供设置页区分“关闭失败，自动重试中”和“关闭失败，请重试关闭”。计数不暴露到用户界面。

### 生命周期

1. 正常释放为该请求开启一次重试预算；清理扫描、认证和驱动的每一步仍尽力执行，不因前一步失败跳过 `powerOff()`。
2. 所有步骤确认成功才置 `kOff` 并清空重试状态。驱动已关但其他清理失败时不虚报全流程完成；再次调用允许幂等清理。
3. 失败进入 `kReleaseFailed`，保持原请求所有权、操作结果和手动入口；新请求继续被拒绝。
4. `tick(now)` 检查请求 ID、失败状态和剩余预算；到期执行一次并递减预算。尝试结束重新读取 `clock_.nowMs()` 记录时间，防止平台调用耗时后紧接着重试。
5. 成功立即停止；预算用完停止自动尝试，保留错误供用户查看。预算不能由自动失败路径重新装满。
6. 用户手动 `close(id)` 可立即再尝试一次；不恢复已耗尽的自动预算。若原预算未耗尽，失败后从此次结束重新等待 1000 ms；成功则取消全部后续重试。
7. `close()` 的旧 ID 仍直接返回过期状态；新请求启动清空所有旧重试数据，双重防止误关后续网络。

沿用服务已有时钟注入，自动尝试只由主循环推进，无 `delay()`、递归重试或无限队列。设置控制器在状态比较中包含 `releaseRetryPending`，避免预算耗尽后提示不更新；业务成功/失败结果不能被收尾重试覆盖。

## 6. 外设处理与证据限制

本机已解析库的静态核验结果如下；依赖缓存不提交也不修改。实施时记录解析版本，若接口不同需复核。

| 对象 | 当前代码证据 | 本期动作与验收边界 |
| --- | --- | --- |
| BMI270 IMU | 默认 `internal_imu=true`，M5Unified 会尝试初始化；BMI270 初始化禁用节能并加载配置；未重写基类返回 false 的 `sleep()` | 初始化前设置 `internal_imu=false`、保持 `external_imu=false`；不调用无效 `Imu.sleep()`。检查冷启动与 MCU 复位后的状态，不能仅凭配置称已断电 |
| 麦克风、扬声器 | 默认允许内部音频；所读初始化路径配置引脚和回调，应用未调用录制或播放；ADV 扬声器禁用回调的寄存器表为空 | 设置 `internal_mic=false`、`internal_spk=false`，不启动音频；不将 `Speaker.end()` 视为编解码器/功放断电证据 |
| LED、红外、SD、外接器件 | 应用未显式启动这些业务；普通系统 LED 配置默认亮度为 0，不代表所有灯的供电 | 保持未使用功能不初始化；核实实际设备是否有活动，不添加无依据的引脚写入 |
| 外接供电 | `output_power` 默认 true，但不能据名字推断 ADV 的有效控制域 | 本期不盲目改该配置；记录板级实现及剩余功耗限制 |
| 键盘、共享 I²C、显示、Flash | 为输入唤醒和现有业务所需 | 保留，不调用共享总线 `end()`，不切公共电源 |

Bosch 数据手册说明 BMI270 在上电复位或自身软复位后处于 suspend；因此冷启动不初始化具有明确依据。但 MCU 复位不必然复位独立供电器件，不能据此承诺所有热重启场景均已待机。[BMI270 数据手册，第 4.4 节](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bmi270-ds000.pdf)

本期基线采用禁止闲置初始化，不添加尚未证实的寄存器关闭序列。外设验收记录包含冷启动、固件热重启、当前硬件状态和测量结果；若确认存在仍活动且可安全关闭的器件，则补充具体器件适配设计后实施，不能将 R-06 标记为已全部验收。无法软件控制或缺少可靠关闭接口的部分明确记录限制。

## 7. 主循环接入顺序

```text
BLE/串口消息处理（沿用）
  → 键盘更新与物理活动报告
  → 唤醒门控；允许时才分发业务键
  → 设置、Wi-Fi、动作、时间同步、Codex tick（沿用）
  → 共享 scheduler.tick：电池采样、必要显示检查等
  → BLE 发送推进（沿用）
  → 重新取单调时间，判断自动息屏
  → 允许显示时合并绘制，唤醒帧完成后恢复背光
  → delay(10)（沿用）
```

平台启动、设置保存或消息处理后重新读取时间，延续主循环已有做法，避免旧 `now` 与新状态时间相减误触发超时。息屏门控不能包住整个循环，也不能跳过控制器 tick。

## 8. 公共能力复用与实现约束

检索范围为 `firmware/src`、相关 `firmware/test`、已解析 M5Cardputer/M5Unified 依赖及既有设置规格。

| 已有能力 | 差距 | 处理 |
| --- | --- | --- |
| 单调时间、`elapsedMs()` | 无 | 直接复用 |
| `ScheduledTaskService` | 缺电量任务 ID | 扩展枚举/校验，不改派发策略 |
| 显示配置及 `ConfigFileStore` | 单字段结构，当前亮度保存会重建配置 | 扩展完整快照，复用原子替换和读回验证 |
| 键盘跟踪与 InputRouter | 缺物理报告和唤醒门控 | 扩展报告；路由业务语义保留 |
| 显示背光与帧缓冲 | 缺统一亮灭策略 | 新建纯状态控制器，复用硬件入口 |
| 电池读取 | 耦合显示、无缓存 | 迁移到独立平台适配器，新建薄缓存服务；不重复实现读取 |
| Codex `makeView()` | 缺可见时间变化比较 | 扩展局部时间快照，复用格式化 |
| Wi-Fi 所有权、release/tick、手动重试 | 无有界自动收尾 | 在原服务扩展，保留调用契约及结果 |

注释只解释唤醒键消费、完整配置保存、周期不补采、重试预算不重置和外设关闭限制等关键意图。单次接线留在 `main.cpp` 或原适配器，不为每个字段建立抽象；新增状态与缓存保持可用 native 测试替身验证。禁止修改第三方缓存、升级依赖、变更 BLE 协议或格式化 LittleFS。
