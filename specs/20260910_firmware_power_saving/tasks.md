# 固件第一期省电：实施任务

> 状态：已确认

日期：2026-09-10。依据：[需求规格](requirements.md)、[技术设计](design.md)。用户回复“继续”，确认任务清单，进入实现。

## 执行约定

- 按编号串行推进，避免 `main.cpp`、显示适配器、设置控制器及集成测试的交叉修改。依赖列表示能力依赖；不因无依赖就同时修改共享文件。
- 每项形成可单独评审的改动，先完成对应新增行为的验证；消费接口的调用方和测试替身随接口迁移同时更新，不留下不可构建的中间状态。
- 完成后在本项记录代码范围、自动化结果与剩余人工关注点，并追加 `changelog.md`；只在满足该任务完成标准后勾选。模块自动化完成不等于实机已验收，整体实机证据由 task-10 收口。
- 下列 `pio` 命令在仓库根目录执行；若 PATH 无该命令，使用现有 `~/.platformio/penv/bin/pio`。不升级依赖或改缓存以规避环境问题。
- 每项只运行相关检查；task-09 汇总运行一次完整固件 native 套件和目标板构建。成功后不无理由重复全量检查。
- 生产代码仅在 Phase 4 修改。无桌面端或协议改动，因此不安排桌面全量测试。
- **首次刷入改造固件前**记录原固件版本、亮度和各场景功耗基线；准备记录不阻塞离线开发，但未取得基线不能声称具有前后功耗对照。刷机时保留原固件与配置，不运行 `uploadfs`。
- 回滚优先撤回当前任务范围；已有后续依赖时按依赖逆序回退，不覆盖用户其他修改。旧固件解析器不接受新显示字段，设备跨版本回滚需使用事先备份的兼容显示配置，不擦除整个文件系统。

## task-02：物理活动与首键唤醒

- 依赖任务：无。
- 修改范围：`firmware/src/platform/keyboard_adapter.*`；新增 `firmware/src/application/power/screen_power_controller.*`；新增 `test_screen_power`、`test_keyboard_activity`，保留并运行 `test_input_router`。
- 公共能力处理：复用 `InputSnapshot`、`KeyPressTracker` 和 `elapsedMs()`；增加包含修饰键的物理报告以及纯状态控制器，不改业务映射或第三方库。
- 代码注释要求：解释首键和释放轮次的消费、按住抑制息屏及时间回绕；不要通过重置按键跟踪器伪造新的按下。
- 完成标准：覆盖 `Awake/Off/WakeUntilRelease` 转换、默认/永不/各时长、按下优先于超时、全部释放后的下一次正常输入。当前本机 TCA8418 `update()` 每次读取一个 FIFO 事件，可沿用快照观察短按；实施时复核版本，不额外消费硬件队列。
- 自动化验证：物理报告覆盖单修饰键、等键数替换、逐次短按/释放、组合键变化；状态机覆盖超时前后 1 ms、持续按住、释放、改时长及回绕。运行 `pio test -d firmware -e native -f test_screen_power -f test_keyboard_activity -f test_input_router`。

- 人工验证关注点：task-10 连续按键、反复唤醒时采样节奏不变；充电指示的硬件限制独立记录。

## task-07：Wi-Fi 有限自动收尾

- 追踪需求：R-05，N-01～N-04。
- 依赖任务：task-04、task-05（用于提示和息屏集成验证）。
- 修改范围：`firmware/src/application/wifi/wifi_service.*`、`application/settings/settings_controller.*` 及必要页面提示；`test_wifi_service`、`test_wifi_scan`、设置控制器及主循环集成用例。只有发现幂等清理差距才修改 `platform/wifi_adapter.cpp`。
- 公共能力处理：扩展既有请求 ID、`release()/tick()/close()` 和时钟注入；新增有限预算与 `releaseRetryPending`，复用手动重试入口，不新增调度任务。
- 代码注释要求：明确首次尝试与额外 3 次预算、结束时计时、预算不因失败或手动操作重新装满，以及旧请求隔离。
- 完成标准：首次失败后每次间隔至少 1000 ms、最多自动重试 3 次；每次尽力执行全部清理，成功即停，耗尽后保留手动入口；手动尝试不恢复预算；设置提示随自动重试状态变化；原业务结果不被覆盖，旧 ID 不影响新请求。
- 自动化验证：逐步注入停止扫描、认证清理、关驱动失败及组合失败；覆盖 999/1000 ms、调用耗时、预算耗尽、延迟不补跑、手动与自动相遇、回绕、旧请求和息屏推进。运行 `pio test -d firmware -e native -f test_wifi_service -f test_wifi_scan -f test_settings_controller -f test_settings_integration -f test_power_integration`，过滤项与实际套件保持一致。
- 人工验证关注点：`设置 → Wi-Fi → 扫描/测试 → 网络信息`，观察结束结果和收尾提示；可控失败用测试替身完成，不要求人为破坏实机无线驱动；真实设备检查操作后驱动状态、电流及 BLE 连续性。
- 回滚边界：服务重试字段、状态比较与提示整体回退至手动重试，保留原 Wi-Fi 所有权机制。
- 待确认问题：无。
