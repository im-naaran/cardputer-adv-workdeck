# 固件第一期省电：项目上下文

> 状态：已确认

日期：2026-09-10。Feature：`firmware_power_saving`。

## 目标与依据

在保留 BLE 在线、现有后台任务和设备交互的前提下，实现自动息屏、停止无效绘制、独立电量采样及闲置外设控制。

用户已确认：首键只点亮屏幕；显示与后台运行分开；Wi-Fi 关闭失败允许自动收尾。电量统一每 60 秒读取，按键不触发采样。

本期边界：默认 10 分钟自动息屏，可选永不/1/5/10/30 分钟；只停止背光与绘制，保留 BLE、后台任务及必要共享总线。启动采样一次，之后亮屏、息屏统一每 60 秒采样，唤醒不补采。CPU 降频、BLE 参数和芯片睡眠不纳入本期。完整行为与验收口径见[需求规格](requirements.md)。

## 技术栈与架构

- 固件：PlatformIO、Arduino ESP32、C++17；平台固定 `espressif32@6.7.0`，M5Cardputer 引用 `1.2.0`。
- `firmware/src/main.cpp` 串行处理输入、BLE 消息、应用控制器、调度和绘制，循环末尾 `delay(10)`。
- `application/` 管理设置、页面及业务，`core/` 提供调度和协议等公共能力，`platform/` 封装显示、键盘、时钟、Wi-Fi 和存储。
- `firmware/test/` 有 native 策略测试及主循环集成测试；真实功耗和设备交互需单独验收。

## 当前实现与复用点

| 范围 | 当前证据 | 后续规划方向 |
| --- | --- | --- |
| 显示 | `main.cpp` 通过重绘标记绘制，每 60 秒还会请求刷新；绘制读取电量 | 增加亮灭状态，绘制消费电量缓存，保留时间文字刷新需求 |
| 背光 | `platform/display_adapter.cpp` 提供 `setBrightness()` | 复用背光入口，运行时息屏不覆盖用户亮度 |
| 键盘 | `platform/keyboard_adapter.cpp` 解析物理键；单独修饰键没有普通业务事件 | 扩展物理活动与按住状态，消费唤醒输入 |
| 配置 | `application/settings/display_config.h` 只有亮度；设置控制器保存时构造亮度配置 | 扩展原显示配置；所有保存入口必须保留新增字段 |
| 调度 | `core/scheduled_task_service.*` 有 8 个槽，当前定义 3 类任务 ID，基于单调时间 | 复用周期调度，增加独立电量任务所需 ID 校验；不创建第二套调度器 |
| Wi-Fi | `application/wifi/wifi_service.cpp` 已有释放和失败状态；失败保留请求所有权；设置提供手动重试 | 在服务层扩展有间隔、有上限的收尾重试，保留请求隔离 |
| 外设 | 显示初始化直接使用 `M5.config()`；本机 M5Unified 配置默认允许内部 IMU、麦克风、扬声器初始化 | 逐项核实初始化、硬件待机和共享资源，再决定关闭方式 |

## 约束与风险

- 本轮仅写本规格目录，不修改固件、依赖、桌面端或协议。
- 键盘及必要共享 I²C 保持可用；息屏不终止后台任务、BLE 会话或正在使用的 Wi-Fi 请求。
- 只关闭背光并不代表 CPU 睡眠；不在第一期引入降频、无线参数调整或 Light/Deep-sleep。
- 不初始化外设不等于硬件已断电，关闭方案必须基于当前依赖和设备事实；无法软件关闭的器件记录限制。
- 配置复用现有存储错误语义，不格式化 LittleFS，不要求覆盖文件系统镜像；临时亮灭状态不写 Flash。
- 电量是估算值，无效读数显示未知；不依赖充电状态改变策略。
- 所有计时应覆盖单调计时回绕；重试不得阻塞主循环或影响后续请求。
- 自动化可证明策略和调用次数，不能替代背光、无线状态和电池侧功耗测量。
